# Security Policy

## Supported Versions

Stellar Abyss is currently in early prototype development. Security fixes are provided for the current `0.1.x` line and the `main` branch.

| Version | Supported |
| --- | --- |
| `0.1.x` | :white_check_mark: |
| `< 0.1` | :x: |

## Reporting a Vulnerability

Please report suspected vulnerabilities privately through GitHub's private vulnerability reporting feature on the repository:

```text
Repository → Security → Advisories → Report a vulnerability
```

Do not open a public issue, pull request, or discussion for an undisclosed vulnerability.

Please include, when available:

- a clear description of the issue;
- the affected version, commit, or branch;
- reproducible steps or a minimal proof of concept;
- the expected and actual behavior;
- the possible security impact;
- a suggested mitigation or fix.

We aim to acknowledge a report within five business days. We will investigate the report, keep the reporter informed when there is meaningful progress, and coordinate disclosure after a fix or mitigation is available. Reports that are out of scope, cannot be reproduced, or do not represent a security issue may be declined with an explanation when practical.

Please do not include real credentials, private personal data, or destructive payloads in a report. If private vulnerability reporting is unavailable, contact the repository owner through GitHub and request a private channel before sharing technical details.

## Scope

This policy covers the source code, dependencies, build configuration, GitHub Actions, repository configuration, and any security issue that affects the browser application or its users.

Gameplay bugs, balance issues, visual defects, and ordinary feature requests should be opened as regular GitHub issues instead.
